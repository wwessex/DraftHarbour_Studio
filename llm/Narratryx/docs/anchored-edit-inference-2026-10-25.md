# Source-anchored editing workflow pilot — 25 October 2026

On four small original copyediting fixtures, an experimental patch workflow preserved the exact requested text in **4/4** cases, compared with **1/4** for returning a rewritten passage. Both arms used the same existing `narratryx-craft-v1` developer service, temperature zero and 256 output tokens. Arm order alternated by fixture. There were eight one-message requests, no truncation and no parse/application rejection.

This is a **workflow/application effect**, not new model training, an improvement in v2 weights, a general rewriting result, or a Muse comparison. The fixtures are original AI-authored evaluation text with known duplicate-word repairs and Unicode punctuation. They are not training targets. Four simple cases provide no reliable estimate of broad editorial quality.

## Mechanism

The rewrite arm asks for the whole corrected target passage. The patch arm asks only for JSON containing small exact `before`/`after` anchors. `foundation/anchored_edits.py` checks that the target still equals the captured text, each nonempty anchor occurs exactly once, and edit ranges do not overlap. It applies accepted changes against original coordinates in reverse order. All text outside accepted anchors is preserved from the original target, rather than regenerated by the model.

The helper processes only a supplied selected-target string. It performs no project/file writes, inference, network calls or manuscript application. A model proposal may still be wrong within an accepted anchor; this validator checks application mechanics, not grammar, meaning or literary judgement. The complete edited preview would still require author acceptance. Invalid JSON, absent/ambiguous anchors, stale targets and overlapping edits are rejected; there is no repair fallback using the known answer.

Six CPU tests cover untouched Unicode text, ambiguous/missing anchors, overlap, stale snapshots and multiple edits with original coordinates. The full current foundation suite passed **116 tests**. The helper is not integrated into web/PWA, Tauri, iOS or native macOS. Any integration must retain their captured-selection and explicit acceptance safeguards, define the boundary to UTF-16 editor ranges, and validate platform parity. Creative Rewrite remains a separate task; these duplicate-repair fixtures do not prove this mechanism can perform a substantive rewrite.

## Reproduction and evidence

Source: `curation/anchored-edit-v1/run.py`.

Evidence: `artifacts/anchored-edit-inference-v1/protocol.frozen.json`, `responses.jsonl`, `summary.json`.

The protocol was written before the first request and records exact fixtures, helper/script hashes, the served model/adapter identity, generation allowance and order. Raw responses and application results are preserved. Requests use the existing authenticated loopback service; credentials are read privately and not written to the protocol or results. The app's selected model/configuration and user manuscripts are unchanged. No paid service, upload or model promotion occurred.

This suggests a practical next engineering direction: train/evaluate source-derived structural edit proposals and keep unchanged text under deterministic application control. Genuine author revisions and independent quality review are still needed for claims about editorial taste, pacing, style and narrative improvement.
