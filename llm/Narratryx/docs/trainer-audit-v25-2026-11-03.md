# Installed Unsloth data path audit — 3 November 2026

The [v24 proposal](curriculum-fit-v24-2026-11-02.md) contains 34 prospective training examples and 16 previously exposed validation monitors. This audit runs the installed Unsloth Studio pretokenized dataset preparation and MLX batching functions on each split separately. It uses the cached Qwen tokenizer and compares the resulting batches with the exact token and label rows supplied.

The audit **passed on all 50 records**. Both batch sizes preserved all 3,706 supervised training tokens and 1,709 monitor tokens; the longest record was 499 tokens. The two-record batches masked 153 training and 242 monitor padding tokens. All four targeted trainer-recipe tests passed. The [local audit evidence](../artifacts/trainer-audit-v25/installed-audit.json) records the per-record counts and hashes.

The check compares the installed package versions and source hashes with v21b, verifies the pinned tokenizer files, and runs the v24 rights, source and split verifier. The earlier 28 training rows and 16 monitor rows must reproduce the v21b token data exactly. The six added targets must round-trip to their source text. Each answer receives one supervised end token, and the prompt labels are ignored. The one-record batch check models the intended pilot configuration; two-record batches exercise padding with mixed lengths. Each split must preserve its complete token and label multiset, including any repeated rows. The batch boundaries must cover the full unpadded record and every padded label must be ignored.

The audit does not run a loss calculation, launch a worker, load model weights or measure training memory. No application source, model configuration, prior weights, benchmark, or rights scope was changed. No app build, runtime or device checks were performed for web/PWA, Windows/Linux Tauri, Capacitor iOS or native macOS.
