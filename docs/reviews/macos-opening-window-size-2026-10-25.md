# macOS opening window size — 25 October 2026

The independent native macOS app now opens its welcome and document windows at the current screen's `NSScreen.visibleFrame`, filling the normal desktop work area between the menu bar and Dock. The welcome view is flexible and its window is resizable. A document-only NSView bridge applies the opening frame once when the window is first shown, after AppKit placement/restoration; subsequent activation does not reapply the size. Settings, utility panels and sheets retain their existing sizing.

The macOS source build passed using the native Swift build system and SDK 26.5. A fresh local bundle was signed ad hoc and its signature verified. Actual GUI launch verified both the welcome window and a saved disposable document opening at the usable screen size. Only the current display was exercised; multiple displays and alternative Dock placements were not physically tested. The default development bundle at `~/Library/Caches/DraftHarbour/BuildProducts/DraftHarbour.app` was updated to the GUI-verified executable, build identifier `2026102504`, with its previous bundle preserved. No running author app was stopped or manuscript edited. This is a local development build, not a notarized release.

Scope was explicitly native macOS only. Web/PWA, Windows/Linux Tauri and Capacitor iOS source and generated assets were unchanged. No unrelated test suites or device builds were rerun for this window-sizing change. XCTest remains unavailable in the installed Command Line Tools; compilation and direct GUI checks were performed instead.
